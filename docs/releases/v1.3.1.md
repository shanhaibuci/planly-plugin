# Planly Plugin v1.3.1

本版修复 Plugin OAuth scope 选择问题，保留 v1.3.0 的独立 MCP 接入、只读 MCP Apps 使用指导与 Planly Logo；不代表真实桌面完整登录或可视化已验收。

## 修复

- 由既有公开 OAuth 配置生成 `mcpServers.planly.scopes=["gateway:mcp"]`，与 `oauth` 同级，不放入被已测运行时忽略的 `oauth.scopes`。
- 避免宿主照搬 Logto 的 13 项身份/组织 scope 列表，导致请求 `profile` 等未授权权限，同时遗漏 `gateway:mcp`。
- 增加配置缺失、字段误放、额外权限、宽发现列表与未声明 scopes 的回归测试，并更新接入诊断说明。
- 不修改 Gateway/引擎、Logto 应用授权、公开 Client ID、回调、端点或品牌资产；不新增凭据或用户级 MCP。

## 升级

1. 将插件市场 Git ref 切换到 `v1.3.1`，再更新或重新安装 **Planly 场景求解**；若跟随 `main`，刷新市场后确认插件版本为 `1.3.1`。固定旧 tag 的市场不会因刷新自动切换版本。
2. 在插件自带 `planly` MCP 的 Authenticate 入口重新发起 OAuth；旧失败页面不含新配置，应关闭并重新发起。
3. 核对新请求的 scope 应为 `gateway:mcp`，不包含 `profile` 等额外权限。不要分享完整授权 URL、state、code、Cookie 或 Token。
4. 完成登录后开启新会话，使用 `$planly-solver` 查看已有成功任务并请求地图/Gantt；不为验收额外创建任务。

## 验证与限制

- 56 项测试全部通过，包含 Codex 0.155.0 的 4 项原生隔离测试，无跳过；Plugin/Skill 校验、配置生成一致性及差异格式检查通过。
- 原生隔离测试在最小、Logto 式宽列表和缺失 scope 发现信息下，均只请求 `gateway:mcp`；既有 MCP UI 元数据和 HTML 资源传输测试通过。
- 真实公网授权前置检查使用真实发现信息生成请求，Logto 返回 303 进入登录交互，未出现 `invalid_scope`；未登录、未同意、未换 Token，不等于完整 OAuth 验收。
- GPT Desktop 更新后的完整 OAuth、MCP Apps 会话渲染/全屏、地图网络与回放仍待验证，详见 [验收清单](../acceptance.md) 与 [scope 规范](../oauth-scopes.md)。
- 此发布不部署服务、不改变用户客户端配置；不能用 scope 修复证明地图 CSP 或规划回放问题已解决。
