# Planly Plugin v1.3.8

日期：2026-10-14。发布标签：`v1.3.8`，按用户要求提交并发布，不移动任何既有 tag。未部署 Gateway 或更新用户安装。

**发布不等于问答验收通过。** 原生 Codex 六次最新复测仍有人选归因和回答聚焦问题，尚未达到直接录屏标准；真实 GPT Desktop 未验收。保留失败记录，不将 Skill 指导视为模型输出保证。

## 变更

- 同步 Gateway Skill：确认卡片绑定当前草稿与费用，一次点击完成确认，参数/费用变化使旧确认失效，重复消息不重提。
- 无按钮能力降级简短文字确认，不向业务用户引用 Skill 路径、内部条款或 revision。
- 结果解释主动核查、业务结论优先，可作明确条件的局部比较，不再机械免责；保留任务绑定、时间语义、真实异常与不编造因果边界。
- 不改变公开端点、OAuth、品牌或求解创建接口；Plugin 不包含 Gateway 卡片 HTML。卡片需配套 Gateway 的 presentation=buttons 支持，当前本地实现不代表已部署。

## 验证

包契约、Gateway 自动化、原生 Codex 真实结果回放及本地测试 MCP 确认流分别记录于验收清单。真实任务回放不创建收费任务，不将模拟 MCP 或原生 CLI 当成 GPT Desktop 图形宿主已验收。

## 三类问答收尾修订与已知限制

- 将重复禁止项收敛成“内部核查 / 对外回答结构”：人选比较、已有单计入和同址硬上限分别按最小充分证据作答，不使用客户预制答案。
- 人选比较保留局部比较条件和任务绑定，不把符合目标升级为实际选人原因；确认卡及所有创建门禁未改。
- 用户确认后继续做了一轮聚焦修订：只回答实际疑问，不预设计数误解；用姓名、地址和服务类型定位，结论加关键依据，说清即止。计数口径内部核实，移除前轮未带来稳定效果的强制重读步骤。
- 同一真实 SKU 任务、相同原问题、`gpt-5.5` / `medium` 最新六次独立复测正常结束，但未达到直接录屏标准：人选归因仍有问题，已有单与同址上限核心正确但仍重复和扩展。最新记录在 Gateway `docs/projects/Aux/dispatch-demo/checks/skill-1.3.8-focused-answer/`；前轮十二次记录在 `checks/skill-1.3.8-answer-refinement/`，两轮原文全部保留，不能由静态契约通过推断回答稳定。
