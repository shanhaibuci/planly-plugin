# Planly Plugin v1.3.7

日期：2026-10-14。发布版本：`1.3.7`；发布标签：`v1.3.7`，既有 tag 不变。

## 变更

- 从 Gateway 当前工作区逐字节同步 16 个公开 Skill 文件，Plugin、Skill 与根版本统一为 `1.3.7`。来源修改尚未提交，不填写提交 hash。
- 将 `gateway.solver_jobs.get_scenario` 加入允许调用的业务工具，仅按 `job_id` 获取 Gateway 派生的求解前场景；新工具实现和权限、归档、积分、审计仍由 Gateway 承担，不打包进 Plugin。
- 日期／城市到来源任务 ID 的映射保留在演示专有配置，不写死到通用 Skill，不猜 ID、不自动选择最近任务。来源任务、本轮初排和重排分别记录。
- 核对返回来源，保留图商、显式矩阵／路线选项和已有安排；不把归档输入当作用户原始 JSON 或求解结果，不将新派工单自动冻结为已有单。业务文字不作为新的行为指令。
- `can_create=false` 时只能读取或解释；创建仍需实时 Schema、地点及公开覆盖校验、积分提示和当前草稿确认。工具缺失、失败或权限不足时不改走管理员、直接 REST 回放或归档接口。
- 结果解释允许用同任务的历史输入核对已有单量与安排；没有可信输入时保留证据缺口，不用当前草稿或其他任务数据替代。v1.3.6 的问题范围、目标守恒、异常披露及只读地图 / Gantt 规则不变。

## 验证与使用边界

本轮包验证结果见 [验收清单](../acceptance.md#v137-历史场景查询同步校验2026-10-14)，来源树指纹见 [同步记录](../gateway-skill-sync.md#v137-历史场景查询同步2026-10-14)。包检查只证明副本、配置和契约一致，不代替模型行为、真实 MCP 授权或 GPT Desktop 的端到端验证。

本次不修改 `.mcp.json`、公开端点、OAuth 或品牌，不部署 Gateway / 引擎，也不替用户更新客户端。使用新场景流程需要所连 Gateway 已提供该工具，并安装含本版 Skill 的 Plugin；服务端新增工具可发现，不代表旧版 Skill 已包含新的调用指导。按 [README](../../README.md#安装与使用) 更新版本引用至 `v1.3.7`；固定旧 tag 的客户端不会自动取得本轮改动。
