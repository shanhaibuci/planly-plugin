# Planly Plugin v1.3.6

日期：2026-10-13。状态：本地待发布，未创建或推送新 tag。

## 变更

- 从 Gateway 当前工作区逐字节同步 16 个公开 Skill 文件，Plugin、Skill 与根版本统一为 `1.3.6`。来源尚未提交，不填写提交 hash。
- 回答聚焦当前业务疑问。已有 / 新派 / 全天单量须核对与任务明确绑定的输入和模型可见结果，不能仅凭分配均匀证明已有单已计入。
- 同址工单数量超过单人硬上限可以证明不能全给一人，不证明当前分给多少人最优。没有业务和对照证据，不称“过度拆分”，不虚构遗漏认错，不擅设“同址优先于均衡”。
- 工单归属解释核对双方相关安排；没有决策轨迹或同口径对照，不声称唯一因果或全局最优，不为解释自动创建收费任务。
- 某人某日请假时继承基线已确认规则、目标和冻结 / 可调整边界，只澄清缺失或冲突。新草稿仍需实时 Schema、地点与引用检查、积分提示及明确创建确认。
- 重排后对比工单去向、其他连带换人、服务时间变化与已核对的保留项。地图 / Gantt 按钮只触发所指任务的只读展示。
- 核对服务时间前先读取当前结果摘要 Schema 的时间语义、单位和时区；到达 / 离开不自动等于服务起止，未知时不得用离开减时长推断服务开始或宣称原预约已保留。
- 真实漏单、超上限、预约变化、地图与排程时间不一致仍须披露，不能用成功状态遮盖；Skill 不修复引擎或宿主 UI。

## 验证与使用边界

常规测试共 68 项，64 项通过，4 项可选原生客户端测试未设置 `PLANLY_CODEX_BIN` 按设计跳过；MCP 配置一致性、16 个公开 Skill 文件逐字节比对和 `git diff --check` 通过。包合约检查只验证指导文字、公开配置和版本一致性，不证明模型在真实会话中执行正确。Codex 真实数据行为验证由 Gateway 本轮验证记录单独记录；现有 MCP 授权返回 `invalid_token`，不能声称 live MCP 验收通过，也不能冒充 GPT Desktop 图形渲染、地图联网或全屏验收。

本轮仅修改本地 Skill 副本、版本元数据、文档和测试。没有发布提交 / tag、推送、部署、修改 OAuth / MCP 配置或品牌、更新用户安装。固定 `v1.3.5` 等旧 tag 的客户端不会自动取得本轮改动；正式发布和客户端更新需另行明确操作。本地验证使用独立客户端安装本仓库，不覆盖用户既有配置。
