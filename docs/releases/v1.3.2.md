# Planly Plugin v1.3.2

日期：2026-09-20。

## 修复

- 插件 OAuth scopes 从仅 `gateway:mcp` 更新为 `gateway:mcp` 与 `offline_access`。
- `gateway:mcp` 仍是唯一 Gateway 业务权限；`offline_access` 只允许支持的授权服务器签发 refresh token，不增加资料、组织或管理权限。
- 公开 Client ID、loopback callback、Gateway URL 和 Logto refresh token 轮换策略不变。
- 配置生成、独立 Skill 登录指引和测试统一使用同一精确 scope 列表，并拒绝缺失、乱序或额外权限。

## 根因证据

2026-09-20，GPT Desktop 使用 v1.3.1 重新登录后的 Logto 日志显示 AuthorizationCode 换码成功，但请求 scope 只有 `gateway:mcp`，返回 `tokenTypes=["AccessToken"]`，没有后续 RefreshToken grant。该公开客户端服务端已允许 refresh token 和轮换，因此仅修改服务端开关不能补足客户端缺失的 `offline_access`。

## 升级

1. 将插件市场 Git ref 切换到 `v1.3.2`，再更新或重新安装 **Planly 场景求解**；安装详情页不能直接编辑包内 scope。
2. 重新执行一次 OAuth 登录，使新的授权请求包含 `gateway:mcp offline_access`。旧授权不会因更新包而自动获得 refresh token。
3. 在脱敏日志中确认首次 AuthorizationCode 换码的 token types 同时包含 AccessToken 与 RefreshToken；access token 到期后再确认出现 RefreshToken grant。不要分享完整授权 URL、code、Cookie 或 Token。

## 验证边界

包内测试只验证生成配置和原生授权 URL，不代替 GPT Desktop 的真实换码、Token 安全存储、定时刷新或撤销测试。完整状态见 [验收清单](../acceptance.md) 与 [scope 规范](../oauth-scopes.md)。
