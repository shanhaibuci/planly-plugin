# Planly Plugin v1.3.5

日期：2026-09-30。

## 变更

- 从 Gateway 本次实现工作区逐字节同步 16 个公开 Skill 文件，Plugin、Skill 与根版本统一为 `1.3.5`；来源尚未提交，因此不记录提交 hash。
- 地点模式只根据当前 ImageVersion 的实时 `request_schema` 决定。新草稿采用 Schema 明确首选的集中引用，已有且完全合法的内嵌地点草稿可以保持内嵌，不按镜像名称或版本号分支。
- 显式维护 `location_encoding` 与 `location_validation`。集中模式校验地点集合非空、POI ID 非空且唯一、`referenceIds ⊆ poiIds`、空地点及被引用 POI 坐标；内嵌模式禁止字符串地点引用并要求完整有效地点对象。
- 混合地点在确认前按 Schema 转为集中引用并提升 revision。任一草稿变化都使地点检查和旧确认失效；只有检查为 `passed` 且 `checked_revision` 等于当前 revision 时才可展示确认并调用创建 tool。
- 检查失败禁止创建；地点、ID、引用或坐标修复后必须重新检查、摘要和人工确认，不自动重提收费任务。

## 升级

1. 将 marketplace Git ref 切换到 `v1.3.5`，再更新或重新安装 Planly Plugin。
2. 开启新会话并确认使用当前插件连接；仅在宿主要求时完成 OAuth，不创建第二条用户级 MCP。
3. 新建请求使用 ImageVersion Schema 明确首选的地点结构；既有完整内嵌请求可以保留。Skill 报告地点阻断问题时先修复并重新确认，不绕过门禁或重复提交。

固定旧 tag 的客户端不会自动取得本轮更新；不移动或覆盖任何既有 tag。

## 验证边界

常规测试共 61 项，57 项通过，4 项可选原生客户端测试因未指定 `PLANLY_CODEX_BIN` 按设计跳过。Skill 结构校验、MCP 配置一致性、16 个公开 Skill 文件逐字节比对及 `git diff --check` 通过。

本轮修改 Skill 指导、客户端门禁、Plugin 版本、说明和测试，并与引擎 OpenAPI/Schema 契约说明配套；没有修改 Gateway 或引擎运行时、公开端点、OAuth、`.mcp.json` 或品牌素材。客户端检查不是服务端语义兜底，未加载或绕过 Skill 的调用仍不受保护。

此次已创建并推送发布提交及新 tag `v1.3.5`，但未部署服务，未更新用户已安装插件，未执行真实 OAuth、图形 UI 或收费求解任务。实际验收记录见 [验收清单](../acceptance.md)。
