# 场景分析与 ImageVersion 选择

## 分析目标

先理解用户要解决的规划问题，再选择 ImageVersion。不要一开始要求用户手写 Gateway JSON。

使用最少必要问题确认：

- **对象**：要规划、分配、排序或选择什么；
- **资源**：由哪些人员、车辆、设备或时段承担；
- **规则**：时间窗、班次、技能、容量、区域、顺序、必须或禁止关系；
- **目标**：用户希望降低或提高什么，以及哪些目标不能牺牲；
- **规模**：主要对象数量、资源数量、日期范围、区域和运行频率；
- **地图**：涉及的国家或地区、图商要求以及是否已有距离矩阵；用户提供的地址或地点名称可作为初始输入，不要求用户补充 POI ID 或经纬度；
- **数据**：数据库、Excel、CSV、API、手工表及可提供的脱敏样例；
- **输出**：期望获得的分配、路线、排程、得分、未安排对象或其他结果；
- **运行方式**：一次性试算还是日常重复运行。

把用户明确不能改变的规则标为硬约束，把偏好和优化方向标为目标或软偏好。含义不清时列为未决问题，不自行分类。

## 地图默认推荐

场景需要地图时先检查用户是否明确指定图商：受支持时直接遵照，不因地区默认改写或再询问是否确认；不受支持时说明限制并停止相关解析与创建，不静默替换。

用户没有指定图商时，依据业务地点默认采用：

- 中国境内采用 `AMAP`；
- 中国境外采用 `HERE`；
- 跨境或地区不明确时先澄清业务地点，不猜测图商。

采用前必须验证所选 ImageVersion 的 `supported_map_providers` 包含该图商。不支持地区默认图商时只澄清当前版本实际支持的必要选择，不把区域默认当成能力事实。图商确定后直接用于地址解析与草稿，不要求用户单独回复“确认使用”。在后续信息收集或参数摘要中简短说明建议使用的图商及地区依据，不展示“确认求解版本与图商”或镜像与图商组合选择卡。图商的默认确定不替代地址解析结果确认。

## 查询候选能力

1. 调用 `gateway.image_versions.list_available` 获取当前用户可用版本。
2. 列表为空时说明当前账号没有可用 ImageVersion，停止创建流程并引导用户联系管理员。
3. 对与场景相关的候选调用 `gateway.image_versions.get_detail`。
4. 只依据 Gateway 返回的能力说明、适用和不适用场景、`limits`、`supported_map_providers` 及可用状态比较。
5. 忽略 `import_status` 非 `succeeded` 或明显不可创建的版本。

`get_detail` 即使返回 `constraint_override_schema`、`constraint_override_defaults` 或 `constraint_presets`，本阶段也只缓存为候选版本详情，不解释、不推荐、不选择约束方案，不设置罚分。约束内容必须等 ImageVersion 选定并验证、完成参数阶段的 Schema 组合后再处理。

用户直接给出 ImageVersion ID 或名称时也要实时验证权限、启用状态和详情，不直接沿用历史信息。

## 版本选定与合并说明

- **唯一可用版本**：当前用户仅有一个可用且可创建的版本，详情能力与已知场景相符，且没有影响适用性的未决问题时，默认采用并读取其 `request_schema`。不单独询问是否采用，不要求用户复述镜像名称；把“本次使用推荐的某求解镜像，适合某业务；地点在境外，建议使用 HERE”等简短说明并入后续业务回复，不为说明本身停下来等确认。名称和适配理由必须来自真实详情。
- **不适配或适用性不明**：唯一版本明显不支持场景时说明能力缺口并停止创建；关键信息不足时只补问影响适配的业务问题。不要把“是否坚持使用该镜像”当成解决不适配的办法。
- **用户明确指定**：实时验证指定版本的权限、状态及适配性后直接采用，不重复确认；不适配或不可用时说明原因，不自动改成另一个版本。
- **多个可用版本且用户未指定**：仍推荐首选、必要时的备选并让用户选择。不要把多个可用版本擅自简化成唯一版本来免除选择。

需要比较版本时说明：

- 适配的业务问题；
- 推荐依据；
- 规模、地图或输入限制；
- 当前信息不足或不适用之处。

完成推荐后再集中列出需要用户准备或确认的关键数据。使用面向业务用户的能力名称和理由；除非排障或消除歧义所必需，不把 ImageVersion ID、内部状态或 Schema 术语作为主要表达。

单独询问是否采用推荐 ImageVersion 时，紧跟一个不超过 20 个汉字的业务推荐理由，例如“适合派单与路径规划”。不要在该问题中同时选择约束方案、罚分或其他下游参数。

默认采用和用户显式选择都可以完成版本选定，但必须记录真实来源，不能把默认采用记为用户已确认。版本选定不等于创建授权；所有实际创建仍须经过当前完整草稿与积分摘要的最终确认。不得把版本推荐和约束方案选择合并为同一个问题。用户偏好可以影响版本推荐，但不得作为未定义创建字段提交 Gateway。

## 阶段产物

阶段结束时形成场景摘要和版本选择摘要：

```yaml
scenario:
  objects: []
  resources: []
  rules: []
  objectives: []
  scale: {}
  data_sources: []
  expected_outputs: []
  open_questions: []
image_version:
  id: "<selected and verified id>"
  reason: "<selection reason>"
  limitations: []
  resolved: true
  selection_source: sole_compatible
```

示例表示默认采用唯一适配版本；用户已明确指定或从多个候选中选择时，`selection_source` 为 `user_explicit`。来源只保存在会话状态，不进入创建 API。

ImageVersion 已选定并验证（`resolved=true`）后即可读取其 `request_schema`，不为唯一适配版本增加确认轮次。场景仍有未决问题不一定阻止进入参数构建，但影响版本适用性或硬约束的问题必须先解决。
